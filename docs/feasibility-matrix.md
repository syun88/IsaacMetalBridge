# Feasibility matrix

IsaacMetalBridge is an unofficial experimental compatibility layer.
It is not affiliated with, endorsed by, sponsored by, or supported by Apple Inc. or NVIDIA Corporation.

Classifications describe the current repository at the audited revisions. “Architecturally possible” is not a working implementation claim.

| Capability | Classification | Evidence / missing work |
|---|---|---|
| Linux ARM64 Isaac Sim 6.0.1 package/image | Verified Base and Full startup | Official ARM64 image is loaded; the real compatibility checker and official Base and Full experiences reached `app ready` under Apple `container`. |
| Apple `container` ARM64 Linux VM | Verified available | Apple `container` 1.1.0 is installed; its service is running and a real guest returned `aarch64`. |
| CPU PhysX | Verified rigid-body gravity/contact slice | `--physics-smoke-output` uses Isaac's installed `DynamicCuboid` and `FixedCuboid`, the real Kit timeline, MBP broadphase, GPU dynamics disabled, and transform readback enabled. Base and Full runs dropped the 1 m cube from z=2.5 m to the correct resting center z=0.5 m and wrote checked JSON. Articulations, joints, complex collision shapes, and long workloads remain unvalidated. |
| Vulkan loader/device discovery | Verified prototype only | Khronos Linux loader and real Kit load the IMB manifest/library and enumerate `IsaacMetalBridge NVIDIA-compat (Apple M4)`. The ICD remains non-conformant. |
| Vulkan compute commands | Verified supported subset | Standard Vulkan buffer/memory, image and texel-buffer descriptors, push constants, translated SPIR-V pipelines, command submission, fences, and readback execute through vsock and real Metal. Probes validate `[6,7,8,9]` storage-buffer output and `[8,9,10,11]` R32_UINT texel-buffer output. Unsupported FP64 and partially-bound RTX submissions remain skipped. |
| Vulkan raster commands | Verified narrow prototypes | The fixed RGBA8 pipeline produced a checked 64×64 triangle PNG. The exact observed Kit UI pipeline also produces real application chrome through Metal. General graphics remain absent. |
| Vulkan ray tracing | Verified bounded scene slice | The probe and real Isaac trace build KHR BLAS/TLAS compatibility objects backed by Metal and dispatch real intersection rays. Scene-state v11 transports authored Meshes, native scenegraph instance proxies, and bounded current-time PointInstancer prototype expansions with composed world transforms, producing deterministic per-occurrence Metal BLASes. Full verified Cube, Ground, two native references, and three visible of four authored PointInstancer entries as `instanceProxyMeshes=2 pointInstances=3 pointInstanceMeshes=3`, followed by one seven-instance TLAS. `--animate-demo` samples real timeline time and refreshes transforms/instances while reusing content-identical BLASes; a 300-frame Full run reached sequence 52 and exited zero after 94 seconds. The active viewport-camera frame can also be exported through the bounded RGB sensor contract. General Vulkan RT shader semantics, nested instancing, per-instance primvar overrides, animated material inputs, and robust skinning/deformation are not implemented. |
| Vulkan sparse images | Verified Metal tile mapping subset | Sparse-image requirements, tile dimensions, mip storage, and map/unmap operations are mirrored to real Metal sparse heaps and enabled by default. The real-container probe validates RGBA8 map/unmap. Broader formats and all streaming patterns remain incomplete. |
| Metal ray tracing | Verified execution on current host | Real primitive/instance acceleration structures and a 64×64 probe plus the 1280×720 viewport-camera dispatch execute on Apple M4; the completed camera frame is resampled for the verified 640×480 RGB sensor output. |
| USD lighting | First SphereLight/DistantLight/DomeLight, authored/normal-mapped normals, and hard shadows bridged | Protocol 1.13 carries the first stage records into bounded Metal hit shading, including transformed distant direction, exposure-adjusted intensity, radius/angle, and dome ambient color. Scene-state v11 resolves every USD Mesh normal interpolation mode, Metal transforms and barycentrically interpolates the three corner normals, and a derived/orthogonalized TBN basis applies an RGB tangent-space normal map; geometric face normals remain the fallback. Secondary TLAS rays provide SphereLight/DistantLight hard visibility. Multiple lights per schema, area/soft shadows, and RTX light semantics remain incomplete. |
| USD materials | Base, parameter, emission, and normal texture maps plus direct constants verified | Scene-state v11 resolves direct bound `UsdPreviewSurface`/OmniPBR base color (or displayColor fallback), the no-file `UsdUVTexture.inputs:fallback`, and local file-backed base-color, roughness, metallic, RGB emission, or RGB tangent-space normal images. It resolves `UsdPrimvarReader_float2`, a standard `UsdTransform2d` chain, and every USD primvar interpolation mode; scale-rotate-translate is baked into corner UVs before the Metal hit shader barycentrically samples them. It decodes at most 4096x4096 RGBA8 and preserves scalar output channels. Maps share one complete UV source in this bounded version. A validated material descriptor supplies up to five image IDs, with at most 16 unique images bound per TLAS. Full published `parameterTextures=2 normalTextures=1 uvTransforms=1` and logged Cube `normal:8x8[rgb-tangent]`; separate tests prove spatial emission and normal response. Authored tangent primvars/normal strength, masks, different UV sources within one material, UDIM/mips/color-management equivalence, and general MaterialX/RTX shading remain incomplete. |
| CUDA Driver API | Verified startup prototype | The tested Driver API/private export-table subset lets Kit, PhysX startup, and Warp discover one compatibility device; general kernel execution is absent. |
| PTX conversion | Unknown | Toolchain, licensing, correctness, and feature coverage need research. |
| CUDA streams | Startup handles only | Stream create/query/synchronize/destroy calls are implemented for startup, without general CUDA ordering or kernel semantics. |
| CUDA events | Startup handles only | Event create/record/query/synchronize/destroy calls are implemented for startup, without CUDA timestamp semantics. |
| NVML | Requires Linux guest modification | A compatibility library could answer a subset, but truthful telemetry mapping is undecided. |
| GPU PhysX | Blocked by NVIDIA private technology | Depends on NVIDIA CUDA/GPU implementation details not exposed by this project. |
| Warp | Device discovery verified | Warp 1.13.0 reports the IMB CUDA compatibility device; arbitrary Warp kernels are not validated. |
| Isaac Lab | Unknown | Depends on Isaac Sim, Warp, PyTorch/CUDA, memory capacity, and training workloads. |
| RTX Camera | Bounded Metal RGB contract verified; native annotator incomplete | The active USD camera drives the real viewport-camera Metal frame. `--camera-sensor-output` produced checked 640×480 RGB/JSON from that completed frame without creating the additional Render Product that triggered Render Graph/multiTick/Sensor failures. NVIDIA's Replicator `rgb` CPU array remains unsupported, so native RTX Camera annotator equivalence is not claimed. |
| RTX LiDAR | Not yet equivalent | Metal ray intersection exists, but NVIDIA RTX LiDAR timing, materials, returns, and sensor interfaces are not implemented. |
| GUI | Interactive Full chrome and validation viewport verified | A native macOS viewer shows the real Full Kit menus, panels, toolbar, Stage, Property, and Content UI, forwards pointer/keyboard input through Carbonite, and presents NVIDIA Simple Grid with its actual wire texture, matched Mesh transform, and axes. |
| WebRTC | Out of scope | Requires a working renderer and networking validation first. |
| Host/guest vsock | Verified available | `imb-container-host` uses Apple's `ContainerClient.dial`; a real ARM64 guest completed IMB 1.13 sparse-image mapping, generic/texel-buffer compute, SPIR-V pipeline creation, fixed/UI raster, acceleration structures, live-camera/SphereLight/DistantLight/DomeLight ray dispatch, and final frame delivery over the returned full-duplex file handle. |
| Metal buffer/compute primitive | Verified available | Real `MTLBuffer`, upload/readback, `ADD_U32` compute, and command-buffer fence produced `[6,7,8,9]` from `[1,2,3,4] + 5` on Apple M4, including through a standard Vulkan dispatch. |
| Dedicated VirtIO GPU | Requires Apple container modification | No GPU device is configured in audited source; VZ extension wiring is needed and VZ support must exist. |
| Shared-memory data plane | Unknown | No verified coherent shared-memory mechanism has been selected. |
