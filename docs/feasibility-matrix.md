# Feasibility matrix

IsaacMetalBridge is an unofficial experimental compatibility layer.
It is not affiliated with, endorsed by, sponsored by, or supported by Apple Inc. or NVIDIA Corporation.

Classifications describe the current repository at the audited revisions. “Architecturally possible” is not a working implementation claim.

| Capability | Classification | Evidence / missing work |
|---|---|---|
| Linux ARM64 Isaac Sim 6.0.1 package/image | Verified Base and Full startup | Official ARM64 image is loaded; the real compatibility checker and official Base and Full experiences reached `app ready` under Apple `container`. |
| Apple `container` ARM64 Linux VM | Verified available | Apple `container` 1.1.0 is installed; its service is running and a real guest returned `aarch64`. |
| CPU PhysX | Verified rigid-body gravity/contact slice | `--physics-smoke-output` uses Isaac's installed `DynamicCuboid` and `FixedCuboid`, the real Kit timeline, MBP broadphase, GPU dynamics disabled, and transform readback enabled. Base and Full runs dropped the 1 m cube from z=2.5 m to the correct resting center z=0.5 m and wrote checked JSON. Articulations, joints, complex collision shapes, and long workloads remain unvalidated. |
| Vulkan loader/device discovery | Verified prototype only | Khronos Linux loader and real Kit load the IMB manifest/library and enumerate `IsaacMetalBridge NVIDIA-compat (Apple M4)`. The ICD remains non-conformant. |
| Vulkan compute commands | Verified supported subset | Standard Vulkan buffer/memory, 2D/3D image, texel-buffer, and independent sampler descriptors, push constants, translated SPIR-V pipelines, command submission, fences, and readback execute through vsock and real Metal. Probes validate `[6,7,8,9]` storage-buffer output, `[8,9,10,11]` R32_UINT texel-buffer output, an exact 32-byte 2x2x2 image round trip, exact software-FP64 binary64 decode/encode plus `PackDouble2x32`, and captured depth/volume shaders on Apple M4. SPIR-V descriptor decorations/names are correlated with SPIRV-Cross's compact Metal argument IDs; all 1,270 argument fields across 202 compute modules map, including sparse binding sets, aliases, and generated numeric `m_ID` names. The real Full trace creates 203 of 204 requested Metal pipelines: 198 execute by default, including 21 declaration-only matrix modules and eight exact captured true-use fixtures. The first seven retain their checked position/image outputs, while `c93eebdfc4dd964b` changes only a binary64 camera-origin component and moves a real 3D noise lookup/storage result from `[0,0,0,0]` to `[11,0,0,0]`; 5 other true-use software-FP64 matrix pipelines stay compile-only, and one 64-bit atomic compare-exchange shader remains unavailable. The latest protocol-1.14 Full Warehouse/Franka rerun preserved mipmapped 2D UI level-zero compatibility, deferred pre-manifest scene traces without poisoning the Render Graph, reached `app ready`, ROS 2 Jazzy, 824 TLAS instances, and a checked textured 1440x900 frame before exiting zero. Partially-bound unsupported RTX submissions remain skipped. |
| Vulkan raster commands | Verified narrow prototypes | The fixed RGBA8 pipeline produced a checked 64×64 triangle PNG. The exact observed Kit UI pipeline also produces real application chrome through Metal. General graphics remain absent. |
| Vulkan ray tracing | Verified bounded scene slice | The probe and real Isaac trace build KHR BLAS/TLAS compatibility objects backed by Metal and dispatch real intersection rays. Scene-state v13 transports authored Meshes, native scenegraph instance proxies, bounded current-time PointInstancer prototype expansions, disjoint material-bound GeomSubset faces, and tagged Warehouse Barcode/WallBoard alpha cutouts with composed world transforms, producing deterministic per-occurrence Metal BLASes. Stable fallback normal/TBN bases preserve a Mesh when one triangle has degenerate geometry or UVs; Full Warehouse plus Franka built all 824 instances from transported geometry with zero native bounds matches. Independent camera and static sequences kept `meshSequence=1` while advancing `sceneSequence` to 2 and reused the current TLAS from a header-only read. Full also verified Cube, Ground, two native references, and three visible of four authored PointInstancer entries as `instanceProxyMeshes=2 pointInstances=3 pointInstanceMeshes=3`, followed by one seven-instance TLAS. `--animate-demo` samples real timeline time and refreshes transforms/instances while reusing content-identical BLASes; a 300-frame Full run reached sequence 52 and exited zero after 94 seconds. The active viewport-camera frame can also be exported through the bounded RGB sensor contract. General Vulkan RT shader semantics, arbitrary opacity/translucency, nested instancing, per-instance primvar overrides, animated material inputs, and robust skinning/deformation are not implemented. |
| Vulkan sparse images | Verified Metal tile mapping and compressed-upload subset | Sparse-image requirements, tile dimensions, mip storage, ordered buffer/image copies, and map/unmap operations are mirrored to Metal sparse textures and enabled by default. The Apple M4 container probe validates RGBA8 residency plus BC3 sRGB and BC5 UNORM map/upload/unmap. Broader formats and all streaming patterns remain incomplete. |
| Metal ray tracing | Verified execution on current host | Real primitive/instance acceleration structures and a 64×64 probe plus the 1280×720 viewport-camera dispatch execute on Apple M4. Every scene traces one primary ray per output pixel and secondary hard-shadow rays by default. `IMB_RAY_SHADOWS=adaptive IMB_RAY_PIXEL_STEP=adaptive` explicitly opts into 2x2/4x4 blocks and complex-scene shadow omission for performance testing. |
| USD lighting | First SphereLight/DistantLight/DomeLight, authored/normal-mapped normals, and hard shadows bridged | Protocol 1.14 and scene-state v13 carry the first stage records into bounded Metal hit shading, including transformed distant direction, exposure-adjusted intensity, radius/angle, and dome ambient color. Every USD Mesh normal interpolation mode is resolved, Metal transforms and barycentrically interpolates the three corner normals, and a derived/orthogonalized TBN basis applies an RGB tangent-space normal map; geometric face normals remain the fallback. Secondary TLAS rays provide SphereLight/DistantLight hard visibility. Multiple lights per schema, area/soft shadows, and RTX light semantics remain incomplete. |
| USD materials | Base, parameter, emission, normal maps, alpha cutouts, direct constants, GeomSubsets, and bounded Warehouse MDL normalization verified | Scene-state v13 resolves Preview/OmniPBR, standard connected textures, and the 12 official Warehouse MDL modules without general MDL execution. It bakes their channel masks, pushcart masks, tint/desaturation, sign/barcode composition, ORM roughness ranges, normal strength, Barcode alpha, and WallBoard `AlphaSelection`; base/emission sampling and final output use correct sRGB transfer. Sources up to 4096x4096 are accepted and larger images downsample to 512px for bounded transport. Independent 192 MiB geometry and 128 MiB texture reservations plus 126 texture slots preserve full geometry. Full published 824 Mesh material parts including 12 tagged alpha-cutout records, 401 parameterized Meshes, 692 parameter textures, 346 normal-textured Meshes, and 67 unique textures. Arbitrary opacity/translucency, authored tangents, different UV sources, UDIM/mips, arbitrary color spaces, and general MaterialX/RTX shading remain incomplete. |
| CUDA Driver API | Verified startup prototype | The tested Driver API/private export-table subset lets Kit, PhysX startup, and Warp discover one compatibility device; general kernel execution is absent. |
| PTX conversion | Unknown | Toolchain, licensing, correctness, and feature coverage need research. |
| CUDA streams | Startup handles only | Stream create/query/synchronize/destroy calls are implemented for startup, without general CUDA ordering or kernel semantics. |
| CUDA events | Startup handles only | Event create/record/query/synchronize/destroy calls are implemented for startup, without CUDA timestamp semantics. |
| NVML | Requires Linux guest modification | A compatibility library could answer a subset, but truthful telemetry mapping is undecided. |
| GPU PhysX | Blocked by NVIDIA private technology | Depends on NVIDIA CUDA/GPU implementation details not exposed by this project. |
| Warp | Device discovery verified | Warp 1.13.0 reports the IMB CUDA compatibility device; arbitrary Warp kernels are not validated. |
| Isaac Lab | Unknown | Depends on Isaac Sim, Warp, PyTorch/CUDA, memory capacity, and training workloads. |
| RTX Camera | Bounded Metal RGB contract verified; native annotator incomplete | The active USD camera drives the real viewport-camera Metal frame. `--camera-sensor-output` produced checked 640×480 RGB/JSON from that completed frame without creating the additional Render Product that triggered Render Graph/multiTick/Sensor failures. NVIDIA's Replicator `rgb` CPU array remains unsupported, so native RTX Camera annotator equivalence is not claimed. |
| RTX LiDAR | Not yet equivalent | Metal ray intersection exists, but NVIDIA RTX LiDAR timing, materials, returns, and sensor interfaces are not implemented. |
| GUI | Interactive Full chrome and validation viewport verified | A native macOS viewer shows the real Full Kit menus, panels, toolbar, Stage, Property, and Content UI, forwards batched pointer/keyboard input through Carbonite, and presents NVIDIA Simple Grid or the official Simple Warehouse plus Franka. Select/Orbit/Pan modes use Ctrl+Option+1/2/3; Orbit forwards Alt+left drag and Pan forwards middle-button navigation to the active real USD camera. In the 824-instance Full scene, Orbit visibly changed the frame, published `sceneSequence=2` with `meshSequence=1`, and reused the current TLAS without a Mesh rematch. |
| WebRTC | Out of scope | Requires a working renderer and networking validation first. |
| Host/guest vsock | Verified available | `imb-container-host` uses Apple's `ContainerClient.dial`; a real ARM64 guest completed IMB 1.14 sparse-image mapping, generic buffer/image/texel-buffer/sampler compute, SPIR-V pipeline creation, fixed/UI raster, acceleration structures, live-camera/SphereLight/DistantLight/DomeLight ray dispatch, and final frame delivery over the returned full-duplex file handle. |
| Metal buffer/compute primitive | Verified available | Real `MTLBuffer`, upload/readback, `ADD_U32` compute, and command-buffer fence produced `[6,7,8,9]` from `[1,2,3,4] + 5` on Apple M4, including through a standard Vulkan dispatch. |
| Dedicated VirtIO GPU | Requires Apple container modification | No GPU device is configured in audited source; VZ extension wiring is needed and VZ support must exist. |
| Shared-memory data plane | Unknown | No verified coherent shared-memory mechanism has been selected. |
