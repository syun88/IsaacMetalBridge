# Protocol architecture

IsaacMetalBridge is an unofficial experimental compatibility layer.
It is not affiliated with, endorsed by, sponsored by, or supported by Apple Inc. or NVIDIA Corporation.

The canonical v1 wire definition is [../protocol/README.md](../protocol/README.md) and the portable ABI header is [../protocol/include/imb_protocol.h](../protocol/include/imb_protocol.h).

The control plane contains version negotiation, discovery, error reporting, Ping/Pong, shutdown, resources, and fences. Protocol 1.20 includes real Metal resources, sparse residency, fixed raster/UI, translated compute, primitive/instance acceleration structures, bounded ray dispatch, the zero-AS empty-stage guide, and real command-buffer completion. `TRACE_RAYS` option bit 4 selects that guide, forbids scene-light options, and permits the live Kit camera record. Linear image formats 8/9/10, ordinary 3D image options, compute execution classifications, independent samplers, SPIR-V binding correlation, and exact push-constant selection remain as described by the canonical wire document. Scene-state v18 carries visible USD Mesh geometry plus bounded material data, retains the separate camera/static sequences and globally deduplicated texture table, appends one bounded complete light list, and uses 232-byte Mesh records. `materialBind` GeomSubsets become disjoint Mesh face records, while the 12 official Warehouse source-asset MDL modules are normalized into bounded base/opacity/roughness/metallic/emission/normal fields. Standard `UsdPreviewSurface`/OmniPBR opacity and opacityThreshold use an explicit v14 material flag; compatible opacity texture channels are composed into transported base alpha. Barcode and WallBoard cutout hits below `0.3333` re-intersect up to 64 layers. A zero standard opacity threshold instead uses bounded front-to-back source-over composition in linear color. SphereLight, every RectLight/DiskLight/CylinderLight sample, and DistantLight shadow rays make the same cutout decision and multiply fractional transmittance through up to 64 blockers. Scene textures are bounded to 512px per axis for transport with separate 192 MiB geometry and 128 MiB image reservations and at most 126 unique images. Native proxies and bounded PointInstancer occurrences remain ordinary per-path Mesh records. Host execution is correctness-first by default; adaptive shadows and pixel blocks are explicit opt-ins. Translated general RTX/Hydra shader semantics, colored absorption and refraction/volume/thin-walled semantics, nested instancing, robust deformation, remaining light schemas, light textures and IES profiles, arbitrary software-FP64 modules beyond the fourteen exact captured fixtures, 64-bit atomics that are not the validated coordination-free compare-exchange case, arbitrary Render Products, bulk queues, and zero-copy sharing remain future work.

`TRACE_RAYS` option bit 5 appends an 8-byte light-list header and up to sixteen validated 120-byte light records without changing the 168-byte base payload. Scene-state v18 uses a 160-byte header and the same complete-list record shape to carry up to eight positional, four distant, and four dome lights. The first 80 bytes preserve the v1.19 shape data: RectLight/DiskLight transformed in-plane axes and half extents, plus CylinderLight axial/radial geometry. The next 36 bytes carry ShapingAPI world axis, cone angle, softness, focus, and focusTint; the final flag bit records explicit API application. An unflagged shaping tail must be all zero. Metal evaluates shaping per emitter sample before opacity-aware visibility and diffuse/specular response. Scene-state v3-v17 remains backward compatible, and the ICD expands old records with a zero shaping tail. IES profiles remain explicitly unsupported.

`DistantLight` record value 7 is OpenUSD's full angular diameter in degrees and is valid over `[0, 360)`. Metal treats zero as one parallel direction and nonzero values as four deterministic spherical-cap directions with independent opacity-aware shadow traversal.

The transport remains abstract. Local tests use child-process pipes. Production-path validation uses a Linux AF_VSOCK listener and a macOS adapter that calls Apple container's existing `ContainerClient.dial(id:port:)`; the complete session has passed in a real ARM64 VM. No dedicated VirtIO GPU or coherent shared memory is claimed.
