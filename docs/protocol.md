# Protocol architecture

IsaacMetalBridge is an unofficial experimental compatibility layer.
It is not affiliated with, endorsed by, sponsored by, or supported by Apple Inc. or NVIDIA Corporation.

The canonical v1 wire definition is [../protocol/README.md](../protocol/README.md) and the portable ABI header is [../protocol/include/imb_protocol.h](../protocol/include/imb_protocol.h).

The control plane contains version negotiation, discovery, error reporting, Ping/Pong, shutdown, resources, and fences. Protocol 1.21 includes real Metal resources, sparse residency, fixed raster/UI, translated compute, primitive/instance acceleration structures, bounded ray dispatch, the zero-AS empty-stage guide, and real command-buffer completion. `TRACE_RAYS` option bit 4 selects that guide, forbids scene-light options, and permits the live Kit camera record. Linear image formats 8/9/10, sparse image format 11 (RGBA32 float), ordinary 3D image options, compute execution classifications, independent samplers, SPIR-V binding correlation, and exact push-constant selection remain as described by the canonical wire document. Scene-state v19 carries visible USD Mesh geometry plus bounded material data, retains the separate camera/static sequences and globally deduplicated material texture table, appends one bounded complete light list plus a separate light-image table, and uses 232-byte Mesh records. `materialBind` GeomSubsets become disjoint Mesh face records, while the 12 official Warehouse source-asset MDL modules are normalized into bounded base/opacity/roughness/metallic/emission/normal fields. Standard `UsdPreviewSurface`/OmniPBR opacity and opacityThreshold use an explicit v14 material flag; compatible opacity texture channels are composed into transported base alpha. Barcode and WallBoard cutout hits below `0.3333` re-intersect up to 64 layers. A zero standard opacity threshold instead uses bounded front-to-back source-over composition in linear color. SphereLight, every RectLight/DiskLight/CylinderLight sample, and DistantLight shadow rays make the same cutout decision and multiply fractional transmittance through up to 64 blockers. Material textures are bounded to 512px per axis for transport with separate 192 MiB geometry and 128 MiB image reservations; light images use a separate 16 MiB reservation, and Metal binds at most 126 combined unique images. Native proxies and bounded PointInstancer occurrences remain ordinary per-path Mesh records. Host execution is correctness-first by default; adaptive shadows and pixel blocks are explicit opt-ins. Translated general RTX/Hydra shader semantics, colored absorption and refraction/volume/thin-walled semantics, nested instancing, robust deformation, Geometry/Portal light schemas, DomeLight HDR textures, broader LM-63/TILT variants, arbitrary software-FP64 modules beyond the fourteen exact captured fixtures, 64-bit atomics that are not the validated coordination-free compare-exchange case, arbitrary Render Products, bulk queues, and zero-copy sharing remain future work.

`TRACE_RAYS` option bit 5 appends an 8-byte light-list header and up to sixteen validated 152-byte light records without changing the 168-byte base payload. Scene-state v19 uses a 160-byte header and the same complete-list record shape to carry up to eight positional, four distant, and four dome lights. The first 80 bytes preserve the v1.19 shape data: RectLight/DiskLight transformed in-plane axes and half extents, plus CylinderLight axial/radial geometry. Bytes 80-119 carry ShapingAPI world axis, cone angle, softness, focus, focusTint, and the explicit-application flag. Bytes 120-151 carry optional RectLight-emission and IES image resources, finite angleScale/multiplier values, texture flags, and reserved zero. Metal evaluates shaping, RectLight sRGB modulation, and the linear Type C IES LUT per emitter sample before opacity-aware visibility and diffuse/specular response. Scene-state v3-v18 remains backward compatible, and the ICD expands old records with zero texture fields.

Protocol 1.22 / scene-state v20 keeps the 152-byte record size and defines texture flag bit 3 as a DomeLight 2:1 latlong environment and bit 4 as Radiance RGBE encoding. For a textured Dome, values 4-12 carry normalized world-space local +X/+Y/+Z axes and values 13-15 stay zero; untextured Dome records retain zeros in values 4-15. The first light image resource is mutually exclusive between Rect emission and Dome environment use. The host validates the resource and basis before Metal samples the environment for background misses, normal-directed diffuse response, and reflected-view specular response. Ordinary bounded images are treated as sRGB; `.hdr`/`.pic` pixels remain RGBE and expand to unclipped linear radiance. Scene-state v3-v19 remains accepted.

`DistantLight` record value 7 is OpenUSD's full angular diameter in degrees and is valid over `[0, 360)`. Metal treats zero as one parallel direction and nonzero values as four deterministic spherical-cap directions with independent opacity-aware shadow traversal.

The transport remains abstract. Local tests use child-process pipes. Production-path validation uses a Linux AF_VSOCK listener and a macOS adapter that calls Apple container's existing `ContainerClient.dial(id:port:)`; the complete session has passed in a real ARM64 VM. No dedicated VirtIO GPU or coherent shared memory is claimed.
