# Protocol architecture

IsaacMetalBridge is an unofficial experimental compatibility layer.
It is not affiliated with, endorsed by, sponsored by, or supported by Apple Inc. or NVIDIA Corporation.

The canonical v1 wire definition is [../protocol/README.md](../protocol/README.md) and the portable ABI header is [../protocol/include/imb_protocol.h](../protocol/include/imb_protocol.h).

The control plane contains version negotiation, discovery, error reporting, Ping/Pong, shutdown, resources, and fences. Protocol 1.16 includes real Metal resources, sparse residency, fixed raster/UI, translated compute, primitive/instance acceleration structures, bounded ray dispatch, the zero-AS empty-stage guide, and real command-buffer completion. `TRACE_RAYS` option bit 4 selects that guide, forbids scene-light options, and permits the live Kit camera record. Linear image format 8 carries four-channel unsigned-byte storage (`VK_FORMAT_R8G8B8A8_UINT` / `MTLPixelFormat.rgba8Uint`), format 9 carries four-channel signed-normalized storage (`VK_FORMAT_R8G8B8A8_SNORM` / `MTLPixelFormat.rgba8Snorm`), and sparse-capable format 10 carries sRGB color storage (`VK_FORMAT_R8G8B8A8_SRGB` / `MTLPixelFormat.rgba8Unorm_srgb`). Ordinary image option bit 1 marks a tightly packed 3D texture, with its 16-bit depth in option bits 16-31; option zero remains the original 2D encoding and option bit 0 remains sparse residency. The verified probes cover exact 2x2x2 transfer and signed-byte preservation, while the depth-consistency fixture uses negative SNORM texels to enter both real neighbor clipping paths. Compute-pipeline creation returns execution-classification bit 0 for actual software-FP64 use and bit 1 when a coordination-free 64-bit compare-exchange kernel must run all logical invocations serially. The host also derives per-pipeline Vulkan set/binding maps from the SPIR-V decorations/names and translated MSL: sets 0-7 use compact argument-buffer IDs, while sets 8 and above use direct Metal buffer/texture/sampler arguments. Generated numeric `m_ID` fields and same-binding aliases are retained. Push constants are resolved from their SPIR-V storage class and result ID/name rather than the first constant-buffer signature, preventing a direct UBO from receiving push data. Compute binding kind 7 adds independent Vulkan samplers and preserves their packed filtering/address/LOD state. Scene-state v14 carries visible USD Mesh geometry plus bounded material data, retains v13's separate camera/static sequences, adds one globally deduplicated texture table, and uses 232-byte Mesh records. `materialBind` GeomSubsets become disjoint Mesh face records, while the 12 official Warehouse source-asset MDL modules are normalized into bounded base/opacity/roughness/metallic/emission/normal fields. Standard `UsdPreviewSurface`/OmniPBR opacity and opacityThreshold use an explicit v14 material flag; compatible opacity texture channels are composed into transported base alpha. Barcode and WallBoard cutout hits below `0.3333` re-intersect up to 64 layers. A zero standard opacity threshold instead uses bounded front-to-back source-over composition in linear color. SphereLight/DistantLight shadow rays make the same cutout decision and multiply fractional transmittance through up to 64 blockers. Scene textures are bounded to 512px per axis for transport with separate 192 MiB geometry and 128 MiB image reservations and at most 126 unique images. Native proxies and bounded PointInstancer occurrences remain ordinary per-path Mesh records. Host execution is correctness-first by default; adaptive shadows and pixel blocks are explicit opt-ins. Translated general RTX/Hydra shader semantics, colored absorption and refraction/volume/thin-walled semantics, nested instancing, robust deformation, soft shadows, arbitrary software-FP64 modules beyond the fourteen exact captured fixtures, 64-bit atomics that are not the validated coordination-free compare-exchange case, arbitrary Render Products, bulk queues, and zero-copy sharing remain future work.

The transport remains abstract. Local tests use child-process pipes. Production-path validation uses a Linux AF_VSOCK listener and a macOS adapter that calls Apple container's existing `ContainerClient.dial(id:port:)`; the complete session has passed in a real ARM64 VM. No dedicated VirtIO GPU or coherent shared memory is claimed.
