# Minimal Vulkan ICD

IsaacMetalBridge is an unofficial experimental compatibility layer.
It is not affiliated with, endorsed by, sponsored by, or supported by Apple Inc. or NVIDIA Corporation.

## Verified scope

The Linux ARM64 guest image contains an experimental Vulkan Installable Client Driver at `/usr/local/lib/libimb_vulkan_icd.so` and a loader manifest at `/usr/local/share/vulkan/icd.d/imb_icd.json`.

The implementation follows Khronos's documented loader/driver discovery ABI:

- exports `vk_icdNegotiateLoaderICDInterfaceVersion`
- exports `vk_icdGetInstanceProcAddr`
- negotiates loader/driver interface version 5 or lower
- uses a version 1.0.1 JSON manifest selected with `VK_DRIVER_FILES`
- initializes dispatchable handles with the loader magic from `vk_icd.h`

Primary reference: [Khronos Vulkan Loader driver interface](https://github.com/KhronosGroup/Vulkan-Loader/blob/main/docs/LoaderDriverInterface.md).

The current driver combines exact Metal compute, fixed raster, and tested Kit UI raster paths with a broader startup compatibility surface:

- Vulkan 1.1 instance/device identity and creation/destruction
- one physical device whose name comes from the live IMB/Metal capability reply
- the feature/limit and extension subset requested by the tested Kit startup, including descriptor indexing, memory budget, dedicated allocation, and timeline semaphores
- memory and queue-family property reporting for the existing shared-buffer/compute research path
- one logical device and 16 queues
- device/queue idle operations
- storage-buffer creation, host-visible/coherent memory, binding, mapping, and readback
- descriptor layouts/sets for storage and uniform buffers, sampled/storage images, independent samplers, and uniform/storage texel buffers
- exact `ADD_U32` plus live SPIR-V-to-MSL compute pipelines
- primary command-pool/buffer recording for bind, push constants, and three-dimensional dispatch
- `vkQueueSubmit`, Vulkan fence wait/status/reset, real Metal fence completion, and result readback
- opaque startup resources for images/views/samplers, render passes/framebuffers, graphics pipelines, pipeline caches, and general descriptor layouts
- one executable RGBA8 image/render-pass/framebuffer/fixed-triangle graphics pipeline with `vkCmdDraw`, queue submit, Metal fence, and checked readback
- one exactly recognized Kit UI graphics pipeline with BGRA8 targets, texture descriptors, copy/upload tracking, indexed draws, ring-buffer offsets, scissors, and synchronous Metal completion
- KHR ray-tracing pipeline/group/SBT compatibility sufficient for the verified probe and observed real-Isaac trace
- KHR triangle BLAS and instance TLAS builds backed by real Metal acceleration structures
- bounded real Metal ray dispatch into RGBA8 for the active Kit viewport camera
- synchronization of the 1280×720 real-Isaac result into Kit's triple-buffered viewport images and one-shot RGB sensor publication at the requested output size
- Vulkan sparse-image requirements, ordered buffer/image transfers, BC3 sRGB and BC5 UNORM uploads, and tile map/unmap backed by Metal sparse textures
- real generic compute execution for supported translated pipelines with buffer, image, independent sampler, and formatted texel-buffer bindings
- binary/timeline semaphores and query-pool lifecycle/results
- synchronous validation/no-op handling for generic graphics submissions outside the fixed triangle and recognized Kit UI paths

The ICD accepts a host connection only when `IMB_VSOCK_PORT` is explicitly set. It performs IMB 1.14 negotiation and requires the live host to advertise Metal buffer, compute, image, fixed raster, UI raster, resource-I/O, and real-fence capabilities before exposing the physical device. Live SPIR-V compute-pipeline creation requires `METAL_SPIRV_COMPUTE`; sparse images require `METAL_SPARSE_IMAGE`; acceleration-structure and ray commands require `METAL_ACCELERATION_STRUCTURE` and `METAL_RAY_DISPATCH`.

## Explicit limitations

This is not a conformant Vulkan implementation and does not report a conformance version. Compute shader modules are sent through the protocol to a pinned SPIRV-Cross build and compiled as real Metal pipelines when supported. The host's software-FP64 preamble preserves binary64 storage ABI while lowering the validated arithmetic to Metal float operations. It classifies the translated selected entry point and returns a creation flag to the guest instead of treating every binary64 matrix member in a generated descriptor struct as executable code. Pipeline creation also correlates SPIR-V descriptor decorations/OpName with SPIRV-Cross's compact argument-buffer IDs; the captured set maps all 1,270 fields across 202 compute modules and prevents sparse Vulkan bindings from being encoded into the wrong Metal slots. Generated numeric resources such as SPIR-V result ID 10 are recovered from SPIRV-Cross's legal MSL name `m_10`. Protocol 1.14 stores each independent `VkSamplerCreateInfo`, validates its packed dispatch record, creates an argument-buffer-capable `MTLSamplerState`, transports linear RGBA8 UINT storage images, and carries tightly packed ordinary 3D RGBA/BGRA images while preserving the original 2D and sparse encodings. The current live Isaac trace creates 203 of 204 requested `MTLComputePipelineState` objects: 198 are execution-enabled, including 21 matrix-typed declaration-only modules and eight exact true-use modules validated by dispatch/output on Apple M4; 5 true-use software-FP64 matrix pipelines are compile-only by default, and the remaining shader requires unavailable 64-bit atomic compare-exchange. The eighth `c93eebdfc4dd964b` fixture changes only a binary64 camera-origin component and checks a sampled/writable 3D-image output transition from `[0,0,0,0]` to `[11,0,0,0]`. The latest protocol-1.14 default completed Full Warehouse/Franka, deferred resolved pure-KHR scene traces while its real USD manifest was still being published, reached `app ready`, verified ROS 2 Jazzy, built all 824 fallback TLAS instances, produced the checked textured scene frame, and exited zero without targeted Render Graph/multiTick/Sensor/Hydra errors. Legal null/partially-bound descriptors and unsupported formats remain skipped without failing the entire RTX queue. General graphics pipelines remain compatibility objects/no-ops outside the verified fixed and Kit UI paths.

Real Isaac RTX creates a small R32_UINT view whose explicit byte range includes one incomplete final texel. The compatibility ICD accepts only that bounded tail case by reducing 1161 requested bytes to 1160 usable bytes. The real-container probe covers both the standard `VK_WHOLE_SIZE` form and this explicit-tail compatibility form; other zero, out-of-buffer, misaligned-offset, and oversized views still fail.

Isaac Kit can also map the same persistent upload allocation from two subsystems before either releases it. The compatibility path accepts a second map only when its resolved offset and size are identical to the active map, returns the same stable backing pointer, and keeps the allocation mapped through a reference count until both unmaps arrive. Different or overlapping ranges still return `VK_ERROR_MEMORY_MAP_FAILED`. The real Apple-container probe validates the two-map/two-unmap case before executing Metal compute.

The verified ray path intersects real scene geometry, but Kit's NVIDIA-only instance producer leaves the observed TLAS descriptor null. Scene-state version 13 preserves v12's 156-byte header and separate camera/static sequences, changes each Mesh record to a 224-byte form, and stores every transported image once in a global deduplicated texture table. The Kit extension resolves `constant`, `uniform`, `vertex`, `varying`, and `faceVarying` USD Mesh normals and float2 primvars. Native scenegraph instance proxies and bounded current-time PointInstancer occurrences remain supported, while `materialBind` GeomSubsets become synthetic stable Mesh paths containing disjoint face sets. `omni.timeline` seconds are converted with the stage time-code rate before OpenUSD evaluates camera, transforms, topology, points, normals, UVs, display color, lights, proxy transforms, prototype data, IDs, and visibility. Static Mesh/material/light bytes are cached until an OpenUSD objects-changed notice arrives; camera-only updates reuse them, while timeline playback deliberately invalidates them. The ICD first reads only the 156-byte header and reuses the fallback TLAS when the static sequence is unchanged. Geometry/material content hashes remain independent of path and world transform, so transform-only occurrences share Metal BLAS/material resources after a real static update. Connected NodeGraph outputs support no-file `UsdUVTexture` fallback colors or standard local files plus `UsdPrimvarReader_float2`; `UsdTransform2d` scale, counter-clockwise rotation, and translation are baked into corner UVs. Source textures are capped at 4096x4096 and downsampled to at most 512px per axis. Maps must share one complete UV source, scalar R/G/B/A selectors are retained, and emission/normal use RGB. The 12 official Simple Warehouse MDL modules are normalized through their bounded channel-mask blends, pushcart masks, tint/desaturation, sign/barcode composition, ORM roughness ranges, and normal-strength reconstruction without executing arbitrary MDL. The official Barcode alpha and WallBoard `AlphaSelection` are baked into base alpha and tagged in material flag bit 6. `MBM1 v2` carries the tag to Metal, which skips alpha values below `0.3333` and re-intersects up to 64 layers. Base/emission texture samples use sRGB-to-linear transfer before lighting and completed linear output is encoded to sRGB. The ICD builds a dedicated Metal BLAS for every unique transported Mesh content record and applies each occurrence's USD world transform in the fallback TLAS. Material geometry duplicates indexed corners into interleaved position/normal/UV/material/emission data; vertex format 6 adds normalized tangent and bitangent vectors derived from triangle positions and transformed UV derivatives. Degenerate geometry normals and zero-area normal-map UV triangles receive stable finite fallback bases. Separate host RGBA8 images are referenced through validated 48-byte `MBM1 v1` or 56-byte `MBM1 v2` descriptors, and Metal can bind up to 126 unique images. Scene-state v3-v12 remains accepted. The latest 2026-08-08 Full Warehouse plus Franka run published 824 material-part Meshes including 12 tagged alpha cutouts, 67 unique textures, 32.1 MiB geometry, and 77.8 MiB texture data; it built all 824 instances with zero native bounds matches. An Orbit update advanced scene sequence 1 to 2, kept mesh sequence 1, and logged `reason=camera-only-update` without a second Mesh rematch. Native BC3 sRGB and BC5 UNORM sparse uploads also pass through Metal. Arbitrary opacity/translucency, authored tangent primvars, different UV sources within one material, UDIMs, mip generation, arbitrary color spaces, nested instancing and per-instance primvar overrides, animated material inputs, robust skinning/deformation, and general MaterialX/OmniPBR graphs remain incomplete.

For ray submissions, the ICD also sends the active Kit viewport camera plus the first USD SphereLight, DistantLight, and DomeLight to Metal. Directional world transform, color, exposure-adjusted intensity, radius/angle, and dome ambient color are validated before use. Isaac's four observed SBT records may still contain zero bytes when submitted; sparse-record ordinal inference normally resolves them. If that lookup is temporarily unavailable, the ICD now recovers only the exact observed `1280x720`, `2560x720`, `160x90`, or `256x144` extent when the linked pipeline contains exactly one group with the corresponding known raygen hash. Unknown extents, absent hashes, and ambiguous matches remain rejected, with separate NV/KHR copy and unresolved/unknown trace counters. The host retains either one normalized geometric face normal or three authored corner normals for every triangle in a supported single-geometry BLAS before Vulkan source buffers can disappear. It applies the TLAS instance cofactor transform, indexes the resulting world normals by Metal instance/primitive ID, and barycentrically interpolates authored triples at the hit coordinate. Vertex-format-6 tangent and bitangent directions use the instance linear transform and are Gram-Schmidt orthogonalized at the hit before normal-map application. Dedicated Metal regressions verify authored-normal interpolation and opposite normal-map texels producing different off-axis lighting. A second Metal TLAS intersection from each lit hit supplies SphereLight/DistantLight hard visibility. Correctness-first execution is the default: `IMB_RAY_SHADOWS=always` and `IMB_RAY_PIXEL_STEP=1`. Explicitly setting both variables to `adaptive` restores the performance experiment that disables secondary shadows above 256 instances and uses 2x2/4x4 primary blocks above 256/512 instances. When `--camera-sensor-output` is requested, the first completed scene frame after live-camera state is available is atomically resampled and published as RGB for the stage extension's one-shot Camera sensor contract. This deliberately avoids a second Replicator Render Product because that unsupported graph produced repeated Render Graph/multiTick/Sensor failures. NVIDIA's Replicator `rgb` CPU array is not claimed as equivalent. Nested instancing and per-instance primvar overrides, animated material inputs, robust skinning/deformation, translated RTX/Hydra material networks, authored tangent semantics, remaining light schemas, soft/area-light shadows, arbitrary Render Products, and native sensor arrays remain incomplete. The ICD must not be installed as a system-wide driver.

## Reproducible validation

Run:

```sh
./scripts/test-vulkan-icd.sh
```

The script builds a Linux ARM64 image, starts the Khronos loader-linked probe in a real Apple container VM, dials its AF_VSOCK listener through Apple's `ContainerClient`, and requires device discovery, storage-buffer and R32_UINT texel-buffer compute, ordered transfer/image readback, BC3 sRGB and BC5 UNORM sparse-image map/upload/unmap, raster, KHR BLAS/TLAS, OPAQUE_FD round-trip, and `VULKAN_RAY_DISPATCH rays=64x64 center=hit corner=miss backend=Metal fence=signaled`. Test containers are removed and a builder started by the script is stopped on exit. Failure logs are preserved and printed instead of being deleted.

The real Full/UI milestone is reproducible with `ACCEPT_EULA=Y ./scripts/run-isaac-sim.sh --experience full --window --simple-grid`. Use `ACCEPT_EULA=Y ./scripts/run-isaac-sim.sh --experience full --window --demo-scene --animate-demo --no-build` for the bounded live-timeline path, or add `--camera-sensor-output build/runtime/camera-rgb.ppm` for the one-shot bounded RGB check. The fixed-raster test writes checked PNG artifacts under `build/artifacts`; the live viewer reads atomic UI frame captures under `build/runtime` and appends input records that the real Kit input provider consumes. The eight captured true-use probes are reproducible by selecting `f5dd5704d7491f17`, `64d94f5901ee0e4f`, `75321ea922defdfc`, `361fde9aceebb12b`, `2eb5c9558c6d3e5a`, `610a7b9aed9f7b98`, `b258118a36125408`, or `c93eebdfc4dd964b` in `IMB_SHADER_HASH` and setting `IMB_EXECUTE_FP64_FIXTURE=1` before `swift run --package-path host imb-shader-probe build/tools/spirv-cross build/isaac-spv-dump`; they compile and dispatch the actual shaders and check a decoded position, two-sampler clipping-plane pixel, panoramic image pixel, panoramic storage-buffer position, motion-origin difference pixel, projected-depth pixel, final-composite clipping-plane early output, or binary64-controlled 3D noise/storage-image result. `IMB_VULKAN_FP64_MATRIX_EXECUTION=1` is a diagnostic opt-in only: declaration-only modules and those eight exact validated modules are enabled by default, while this variable removes the remaining 5 true-use gate. The next Vulkan milestones are exact output validation for those 5 modules, material/shader semantics, additional formats/descriptors, nested instancing, robust skinning/deformation, and native RTX annotator arrays. Capability advertisement must expand only as each call path is executed and validated.
